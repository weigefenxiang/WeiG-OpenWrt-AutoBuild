## شروع سریع: ساخت میان‌افزار در سه گام

**📖 [راهنمای تصویری کامل](https://weigshare.com/posts/WeiG-OpenWrt-AutoBuild-Guide/)**

### 1. انتخاب منبع، دستگاه و بسته‌ها

[**【پیکربندی آنلاین】**](https://www.weigshare.com/wrt/) را باز کنید و به‌ترتیب **【Source】** ← **【Branch】** ← **【Target System】** ← **【Subtarget】** ← **【Target Profile】** را انتخاب کنید. بسته‌های لازم را مشخص کرده و در صورت نیاز **【Advanced menuconfig】**، منطقهٔ زمانی و پوسته را تنظیم کنید. با **【بارگذاری پیکربندی】** می‌توانید فایل پیکربندی `*.json`، `.config` یا `config.buildinfo` را وارد کنید. پیش از ادامه، منبع، دستگاه و افزونه‌ها را بررسی کنید.

### 2. ارسال درخواست ساخت از طریق GitHub

ابتدا [**【وارد GitHub شوید】**](https://github.com/login)، سپس به [**【پیکربندی آنلاین】**](https://www.weigshare.com/wrt/) برگردید و **【شروع ساخت ابری】** ← **【دانلود پیکربندی و بازکردن GitHub】** را بزنید. مرورگر فایل `*.json` را دانلود و فرم GitHub Issue را باز می‌کند. روی رایانه، فایل JSON تازه دانلودشده را به کادر درخواست ساخت بکشید و سپس **【Submit new issue】** را بزنید تا درخواست ارسال شود. ربات در پاسخ، پیوند اجرای ساخت را می‌فرستد.

<details>
<summary><strong>نکات مهم (برای باز کردن کلیک کنید)</strong></summary>

> دکمهٔ **【آزمون】** در نوار شناور پایین سمت راست، خطاهای پیکربندی و پیشنهادهای سازگاری را بررسی می‌کند. با زدن **【دانلود پیکربندی و بازکردن GitHub】** نیز بررسی اولیه خودکار انجام می‌شود.
>
> در صورت وجود مشکل، اصلاح پیشنهادی را اعمال کنید یا **【حفظ و ادامه اجباری】** را انتخاب کنید. این کار اشکال منبع بالادستی را رفع نمی‌کند و ممکن است ساخت ناموفق باشد.
>
> فرم GitHub Issue را از صفحه‌ای که پیکربندی‌کننده خودکار باز کرده ارسال کنید تا اطلاعات از پیش پرشده از دست نرود.
>
> فقط دریافت JSON **ساخت را آغاز نمی‌کند**؛ باید Issue را ارسال کنید.
>
> گذرواژهٔ واقعی، توکن یا اطلاعات محرمانه را در Issues عمومی، درخواست‌ها یا گزارش‌ها منتشر نکنید.

</details>

### 3. دریافت میان‌افزار

پیوند Issue را دنبال کنید یا به [**【Actions → Firmware Download】**](https://github.com/weigefenxiang/WeiG-OpenWrt-AutoBuild/actions/workflows/custom-build.yml) بروید. پس از موفقیت، میان‌افزار را از **【Artifacts】** دریافت کنید. `CONFIG` فایل تنظیمات و `BUILD-LOGS` گزارش تشخیصی است؛ **هیچ‌کدام فایل قابل فلش کردن نیستند**. فایل‌ها **60 روز** نگه‌داری می‌شوند.

## پرسش‌های رایج

<details>
<summary>چرا با بسته‌های زیاد فضای RootFS کم می‌آید؟</summary>

بسته‌ها و وابستگی‌هایشان ممکن است از اندازهٔ بخش RootFS بیشتر شوند. اگر دستگاه پشتیبانی می‌کند، در **【Advanced menuconfig】** ← **【Target Images】** مقدار `TARGET_ROOTFS_PARTSIZE` را مثلاً روی 512 یا 1024 MiB بگذارید. بخش‌های حافظهٔ برخی روترهای سخت‌افزاری ثابت است؛ در آن صورت بسته‌ها را کم کنید. نمونه‌ها: [Issue #233](https://github.com/weigefenxiang/WeiG-OpenWrt-AutoBuild/issues/233).

</details>

<details>
<summary>چرا ساخت طولانی متوقف می‌شود؟</summary>

هر Job روی GitHub-hosted Runner معمولاً شش ساعت فرصت دارد. سقف این پروژه **350 دقیقه** و مهلت اجرای آن **335 دقیقه** است تا گزارش‌ها جمع‌آوری شوند. **ساخت متوقف می‌شود، نه اینکه برای ادامهٔ بعدی مکث کند**.

</details>

<details>
<summary>چطور علت شکست ساخت را پیدا کنم؟</summary>

از **【Artifacts】** فایل `BUILD-LOGS` را بگیرید و نخست `00-SUMMARY.txt` را بخوانید. فضای RootFS، زمان و خطاهای منبع یا وابستگی‌ها را بررسی کنید. [Issue #233](https://github.com/weigefenxiang/WeiG-OpenWrt-AutoBuild/issues/233) را ببینید. پس از اصلاح **Issue تازه** بسازید.

</details>

<details>
<summary>آیا Run قدیمی با تنظیمات جدید کار می‌کند؟</summary>

خیر. Run قدیمی درخواست و نسخه‌های کد و دادهٔ قبلی را به کار می‌گیرد. پیکربندی تازه را در سایت فعلی بررسی و درخواست تازه‌ای ارسال کنید.

</details>
