## Пачатак працы: тры крокі да прашыўкі

**📖 [Поўны дапаможнік з малюнкамі](https://weigshare.com/posts/WeiG-OpenWrt-AutoBuild-Guide/)**

### 1. Абярыце крыніцу, прыладу і пакеты

Адкрыйце [**【Анлайн-канфігуратар】**](https://www.weigshare.com/wrt/) і выберыце **【Source】** → **【Branch】** → **【Target System】** → **【Subtarget】** → **【Target Profile】**. У **【② Выберыце плагіны】** пазначце патрэбныя функцыі, пры патрэбе змяніце **【Advanced menuconfig】**, часавы пояс і тэму. Праз **【Загрузіць канфігурацыю】** можна імпартаваць файл канфігурацыі `*.json`, `.config` або `config.buildinfo`. Праверце налады перад працягам.

### 2. Адпраўце запыт на зборку праз GitHub

Спачатку [**【увайдзіце ў GitHub】**](https://github.com/login), вярніцеся ў [**【Канфігуратар】**](https://www.weigshare.com/wrt/) і выберыце **【Пачаць зборку ў воблаку】** → **【Спампаваць канфігурацыю і адкрыць GitHub】**. Браўзер спампуе `*.json` і адкрые форму GitHub Issue. На камп’ютары перацягніце толькі што спампаваны JSON у поле запыту і націсніце **【Submit new issue】**. Бот адкажа спасылкай на зборку.

<details>
<summary><strong>Важныя заўвагі (разгарнуць)</strong></summary>

> Праверце налады і сумяшчальнасць кнопкай **【Праверка】** на плаваючай панэлі справа ўнізе. **【Спампаваць канфігурацыю і адкрыць GitHub】** таксама запускае праверку аўтаматычна.
>
> Калі знойдзены памылкі, ужыйце рэкамендаванае выпраўленне або выберыце **【Захаваць і працягнуць прымусова】**. Гэта не выправіць памылкі зыходнага кода і зборка можа скончыцца няўдала.
>
> Выкарыстоўвайце форму GitHub Issue, адкрытую канфігуратарам, каб не згубіць загадзя запоўненыя звесткі.
>
> Само спампаванне JSON **не запускае зборку** — Issue трэба адправіць.
>
> Не публікуйце сапраўдныя паролі, токены і іншыя сакрэты ў адкрытых Issues, запытах або журналах.

</details>

### 3. Спампуйце прашыўку

Скарыстайцеся спасылкай з Issue або старонкай [**【Actions → Firmware Download】**](https://github.com/weigefenxiang/WeiG-OpenWrt-AutoBuild/actions/workflows/custom-build.yml). Пасля паспяховага выканання спампуйце прашыўку ў **【Artifacts】**. `CONFIG` — файлы налад, `BUILD-LOGS` — дыягнастычныя журналы; **яны не з’яўляюцца вобразамі прашыўкі для ўсталявання**. Файлы захоўваюцца **60 дзён**.

## Частыя пытанні

<details>
<summary>Чаму для вялікай колькасці пакетаў бракуе месца RootFS?</summary>

Пакеты з залежнасцямі могуць перавысіць памер раздзела RootFS. Калі прылада дазваляе, змяніце `TARGET_ROOTFS_PARTSIZE` у **【Advanced menuconfig】** → **【Target Images】**, напрыклад на 512 або 1024 MiB. На некаторых маршрутызатарах раздзелы flash фіксаваныя, таму прыбярыце пакеты. Прыклады: [Issue #233](https://github.com/weigefenxiang/WeiG-OpenWrt-AutoBuild/issues/233).

</details>

<details>
<summary>Чаму доўгая зборка спыняецца?</summary>

Адно заданне на машыне, якую прапануе GitHub, звычайна абмежавана шасцю гадзінамі. Праект задае **350 хвілін** і спыняе выкананне пасля **335 хвілін**, каб захаваць журналы. Гэта **спыненне, а не паўза для аднаўлення**. Вялікія залежнасці, напрыклад Node.js і Rust, могуць павялічыць час зборкі.

</details>

<details>
<summary>Як знайсці прычыну няўдалай зборкі?</summary>

Спампуйце `BUILD-LOGS` з **【Artifacts】** і прачытайце спачатку `00-SUMMARY.txt`. Праверце RootFS, час і памылкі крыніц ды залежнасцей. Глядзіце [Issue #233](https://github.com/weigefenxiang/WeiG-OpenWrt-AutoBuild/issues/233). Пасля выпраўлення стварыце **новае Issue**.

</details>

<details>
<summary>Ці магу я запусціць стары Run з новымі наладамі?</summary>

Не. Стары Run выкарыстоўвае першапачатковы запыт і зафіксаваныя версіі кода і даных. Праверце новую канфігурацыю ў бягучым канфігуратары і стварыце новы запыт.

</details>

## Распрацоўка і разгортванне

Для працы з сайтам не патрэбныя кланаванне рэпазіторыя і Node.js. Тэхнічныя звесткі па-англійску: [дапаможнік распрацоўшчыка](../docs/DEVELOPER.md) і [апісанне архітэктуры](ARCHITECTURE/ARCHITECTURE.md).

## Menuconfig Catalog

[Menuconfig Catalog](https://github.com/weigefenxiang/WeiG-OpenWrt-Menuconfig-Catalog) публікуе галіны зыходнага кода, профілі прылад, пакеты, залежнасці Kconfig і звесткі пра сумяшчальнасць для сайта і сістэмы зборкі. Абедзве часткі выкарыстоўваюць агульныя даныя; AutoBuild не падтрымлівае другую базу прылад і пакетаў.
