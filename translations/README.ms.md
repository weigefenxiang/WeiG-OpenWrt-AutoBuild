## Mula di sini: bina perisian tegar dalam tiga langkah

**📖 [Panduan bergambar lengkap](https://weigshare.com/posts/WeiG-OpenWrt-AutoBuild-Guide/)**

### 1. Pilih sumber, peranti dan pakej

Buka [**【Halaman penyesuaian】**](https://www.weigshare.com/wrt/) dan pilih **【Source】** → **【Branch】** → **【Target System】** → **【Subtarget】** → **【Target Profile】**. Tandakan pakej yang diperlukan dan ubah **【Advanced menuconfig】**, zon waktu serta tema jika perlu. Anda juga boleh memilih **【Muatkan konfigurasi】** untuk mengimport `build-request.json`, `.config` atau `config.buildinfo`. Semak tetapan sebelum meneruskan.

### 2. Hantar permintaan binaan ke GitHub

[**【Log masuk ke GitHub】**](https://github.com/login) dahulu. Kembali ke [**【Penyesuai】**](https://www.weigshare.com/wrt/) dan klik **【Hantar binaan awan】** → **【Muat turun permintaan dan buka GitHub】**. Fail `*.json` akan dimuat turun dan borang GitHub Issue dibuka. Pada komputer, seret fail JSON ke medan permintaan dan klik **【Submit new issue】**. Bot akan membalas Issue dengan pautan ke proses binaan.

<details>
<summary><strong>Perkara penting (klik untuk buka)</strong></summary>

> Klik **【Uji】** pada bar terapung di penjuru kanan bawah untuk menyemak konfigurasi serta cadangan keserasian. Semakan juga dijalankan secara automatik apabila permintaan dijana.
>
> Jika terdapat masalah, gunakan pembetulan yang disyorkan atau pilih **【Kekalkan dan teruskan secara paksa】**. Tindakan ini tidak membaiki ralat kod sumber huluan dan binaan masih mungkin gagal.
>
> Gunakan halaman GitHub Issue yang dibuka secara automatik oleh penyesuai supaya maklumat pra-isi tidak hilang.
>
> Memuat turun JSON sahaja **tidak memulakan binaan**. Anda mesti menghantar Issue.
>
> Jangan dedahkan kata laluan sebenar, token atau rahsia lain dalam Issue awam, permintaan atau log.

</details>

### 3. Muat turun perisian tegar

Ikuti pautan dalam Issue atau buka [**【Actions → Firmware Download】**](https://github.com/weigefenxiang/WeiG-OpenWrt-AutoBuild/actions/workflows/custom-build.yml). Setelah berjaya, muat turun perisian tegar di **【Artifacts】** pada bahagian bawah halaman. `CONFIG` ialah fail tetapan dan `BUILD-LOGS` ialah log diagnostik; **kedua-duanya bukan imej perisian tegar untuk dipasang**. Fail disimpan selama **60 hari**.

## Soalan lazim

<details>
<summary>Mengapakah RootFS tidak cukup ruang apabila banyak pakej dipilih?</summary>

Pakej dan kebergantungannya mungkin melebihi saiz partisi RootFS. Jika peranti menyokongnya, cari `TARGET_ROOTFS_PARTSIZE` di **【Advanced menuconfig】** → **【Target Images】** dan laraskan, contohnya kepada 512 atau 1024 MiB. Sesetengah penghala fizikal mempunyai ruang flash dan susun atur partisi tetap; kurangkan pakej pada peranti tersebut. Rujuk [Issue #233](https://github.com/weigefenxiang/WeiG-OpenWrt-AutoBuild/issues/233).

</details>

<details>
<summary>Mengapakah binaan dihentikan kerana had masa?</summary>

Satu Job pada GitHub-hosted Runner biasanya terhad kepada enam jam. Projek ini menetapkan **350 minit** dengan had pelaksanaan **335 minit**, supaya log sempat dikumpul. Binaan **dihentikan, bukannya dijeda untuk disambung kemudian**. Kebergantungan besar seperti Node.js atau Rust boleh memanjangkan masa.

</details>

<details>
<summary>Bagaimana cara menyiasat binaan yang gagal?</summary>

Muat turun `BUILD-LOGS` melalui **【Artifacts】** dan baca `00-SUMMARY.txt` dahulu. Semak kapasiti RootFS, had masa, ralat sumber dan kebergantungan. Lihat [Issue #233](https://github.com/weigefenxiang/WeiG-OpenWrt-AutoBuild/issues/233). Selepas pembetulan, buat **Issue baharu**.

</details>

<details>
<summary>Bolehkah saya menjalankan semula Run lama selepas menukar konfigurasi?</summary>

Tidak untuk menguji tetapan baharu. Run lama menggunakan permintaan serta kod dan data asal yang dikunci. Muatkan konfigurasi terkini dan hantar permintaan baharu.

</details>
