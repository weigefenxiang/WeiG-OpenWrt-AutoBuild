## सुरुवात: तीन टप्प्यांत फर्मवेअर

**📖 [चित्रांसह संपूर्ण मार्गदर्शक](https://weigshare.com/posts/WeiG-OpenWrt-AutoBuild-Guide/)**

### 1. स्रोत, उपकरण व पॅकेज निवडा

[**【ऑनलाइन कॉन्फिगरेटर】**](https://www.weigshare.com/wrt/) उघडा आणि **【Source】** → **【Branch】** → **【Target System】** → **【Subtarget】** → **【Target Profile】** निवडा. हवी ती पॅकेज निवडा; गरजेनुसार **【Advanced menuconfig】**, वेळक्षेत्र व थीम बदला. **【कॉन्फिगरेशन लोड करा】** वापरून `build-request.json`, `.config` किंवा `config.buildinfo` आयात करता येते. पुढे जाण्यापूर्वी निवड तपासा.

### 2. GitHub वर क्लाउड बिल्डची विनंती करा

प्रथम [**【GitHub मध्ये लॉगिन करा】**](https://github.com/login), मग [**【कॉन्फिगरेटरमध्ये】**](https://www.weigshare.com/wrt/) परत येऊन **【क्लाउड बिल्ड पाठवा】** → **【विनंती डाउनलोड करून GitHub उघडा】** दाबा. ब्राउझर `*.json` फाईल डाउनलोड करून GitHub Issue फॉर्म उघडेल. संगणकावर JSON फाईल विनंतीच्या चौकटीत ड्रॅग करून **【Submit new issue】** दाबा. बॉट बिल्डची लिंक देईल.

<details>
<summary><strong>महत्त्वाच्या सूचना (उघडा)</strong></summary>

> खाली उजवीकडील तरंगत्या साधनपट्टीतील **【तपासा】** वापरून कॉन्फिगरेशन व सुसंगतता आधी पाहू शकता. विनंती तयार करतानाही तपासणी आपोआप होते.
>
> समस्या आढळल्यास सुचवलेला उपाय लागू करा किंवा **【तसेच ठेवा व सक्तीने पुढे जा】** निवडा. याने मूळ स्रोताची त्रुटी दुरुस्त होत नाही आणि बिल्ड अयशस्वी होऊ शकतो.
>
> पूर्वभरलेली माहिती टिकवण्यासाठी कॉन्फिगरेटरने आपोआप उघडलेलाच GitHub Issue फॉर्म वापरा.
>
> फक्त JSON डाउनलोड केल्याने **बिल्ड सुरू होत नाही**; Issue पाठवणे आवश्यक आहे.
>
> सार्वजनिक Issues, विनंत्या किंवा लॉगमध्ये खरे पासवर्ड, टोकन किंवा गुपिते देऊ नका.

</details>

### 3. फर्मवेअर डाउनलोड करा

Issue मधील लिंक वापरा किंवा [**【Actions → Firmware Download】**](https://github.com/weigefenxiang/WeiG-OpenWrt-AutoBuild/actions/workflows/custom-build.yml) उघडा. यशस्वी झाल्यावर **【Artifacts】** मधून फर्मवेअर डाउनलोड करा. `CONFIG` मध्ये सेटिंग्ज आणि `BUILD-LOGS` मध्ये निदान नोंदी असतात; **त्या फ्लॅश करण्यासाठी फर्मवेअर नाहीत**. फाईल्स **60 दिवस** उपलब्ध असतात.

## नेहमीचे प्रश्न

<details>
<summary>जास्त पॅकेज निवडल्यावर RootFS जागा का कमी पडते?</summary>

पॅकेज व त्यांची अवलंबने RootFS विभाजनापेक्षा मोठी होऊ शकतात. उपकरण परवानगी देत असल्यास **【Advanced menuconfig】** → **【Target Images】** मधील `TARGET_ROOTFS_PARTSIZE` 512 किंवा 1024 MiB करा. काही प्रत्यक्ष राउटरचे फ्लॅश विभाजन बदलत नाही; त्यासाठी पॅकेज कमी करा. [Issue #233](https://github.com/weigefenxiang/WeiG-OpenWrt-AutoBuild/issues/233) पाहा.

</details>

<details>
<summary>खूप वेळ चालणारा बिल्ड का थांबतो?</summary>

GitHub-hosted Runner वरील एका Job ची साधारण सहा तासांची मर्यादा असते. प्रकल्पात **350 मिनिटांची** मर्यादा असून लॉगसाठी अंमलबजावणी **335 मिनिटांनी** थांबते. **हे थांबवणे आहे, पुढे सुरू करण्यासाठी विराम नाही**.

</details>

<details>
<summary>बिल्ड अयशस्वी झाल्यास कारण कसे शोधायचे?</summary>

**【Artifacts】** मधून `BUILD-LOGS` डाउनलोड करा व प्रथम `00-SUMMARY.txt` वाचा. RootFS, वेळ, स्रोत कोड आणि अवलंबने तपासा. [Issue #233](https://github.com/weigefenxiang/WeiG-OpenWrt-AutoBuild/issues/233) पहा. दुरुस्तीनंतर **नवा Issue** तयार करा.

</details>

<details>
<summary>नव्या सेटिंग्जसाठी जुना Run पुन्हा चालवता येतो का?</summary>

नाही. जुना Run जुन्याच विनंतीसह ठरवलेला कोड व डेटा वापरतो. नवी कॉन्फिगरेशन तपासून नवी विनंती पाठवा.

</details>
