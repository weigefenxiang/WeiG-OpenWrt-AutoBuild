## தொடங்குவது எப்படி: மூன்று படிகளில் firmware

**📖 [படங்களுடன் முழுமையான வழிகாட்டி](https://weigshare.com/posts/WeiG-OpenWrt-AutoBuild-Guide/)**

### 1. மூலம், சாதனம், தொகுப்புகளைத் தேர்வு செய்யுங்கள்

[**【ஆன்லைன் கட்டமைப்பாளரை】**](https://www.weigshare.com/wrt/) திறந்து **【Source】** → **【Branch】** → **【Target System】** → **【Subtarget】** → **【Target Profile】** என்பவற்றைத் தேர்ந்தெடுக்கவும். தேவையான தொகுப்புகளைக் குறித்துவிட்டு, வேண்டுமானால் **【Advanced menuconfig】**, நேர மண்டலம் மற்றும் தீம் அமைப்புகளை மாற்றவும். **【கட்டமைப்பை ஏற்று】** மூலம் `build-request.json`, `.config`, `config.buildinfo` ஆகிய கோப்புகளை இறக்குமதி செய்யலாம். தொடரும் முன் தேர்வுகளைச் சரிபார்க்கவும்.

### 2. GitHub-ல் மேகக் கட்டமைப்புக் கோரிக்கை அனுப்புங்கள்

முதலில் [**【GitHub-ல் உள்நுழையுங்கள்】**](https://github.com/login). பிறகு [**【கட்டமைப்பாளருக்குத்】**](https://www.weigshare.com/wrt/) திரும்பி **【மேகக் கட்டமைப்பைச் சமர்ப்பி】** → **【கோரிக்கையைப் பதிவிறக்கி GitHub-ஐத் திற】** என்பதை அழுத்துங்கள். உலாவி `*.json` கோப்பைப் பதிவிறக்கி GitHub Issue படிவத்தைத் திறக்கும். கணினியில் JSON கோப்பைக் கோரிக்கைப் பெட்டிக்குள் இழுத்து **【Submit new issue】** என்பதை அழுத்துங்கள். உருவாக்கப் பணிக்கான இணைப்பைப் பாட் பதிலளிக்கும்.

<details>
<summary><strong>முக்கிய குறிப்புகள் (விரிக்கவும்)</strong></summary>

> கீழ் வலப்புற மிதக்கும் கருவிப்பட்டையில் **【சோதனை】** என்பதை அழுத்தி அமைப்புச் சிக்கல்களையும் பொருந்துதல் பரிந்துரைகளையும் முன்கூட்டியே பார்க்கலாம். கோரிக்கையை உருவாக்கும்போதும் சோதனை தானாக நடக்கும்.
>
> சிக்கல் இருந்தால் பரிந்துரைத்த திருத்தத்தைப் பயன்படுத்தவும் அல்லது **【அப்படியே வைத்து கட்டாயமாகத் தொடரவும்】** என்பதைத் தேர்ந்தெடுக்கவும். இது மூலக் குறியீட்டின் பிழையைச் சரிசெய்யாது; உருவாக்கம் தோல்வியடையலாம்.
>
> முன்பே நிரப்பிய தகவல் இழக்கப்படாமல் இருக்க கட்டமைப்பாளர் தானாகத் திறந்த GitHub Issue படிவத்தையே பயன்படுத்தவும்.
>
> JSON கோப்பை மட்டும் பதிவிறக்கினால் **உருவாக்கம் தொடங்காது**; Issue-ஐச் சமர்ப்பிக்க வேண்டும்.
>
> பொதுவான Issues, கோரிக்கைகள் அல்லது பதிவுகளில் உண்மையான கடவுச்சொல், டோக்கன் போன்ற இரகசியங்களைப் பகிர வேண்டாம்.

</details>

### 3. firmware-ஐப் பதிவிறக்குங்கள்

Issue-இல் உள்ள இணைப்பைத் திறக்கவும் அல்லது [**【Actions → Firmware Download】**](https://github.com/weigefenxiang/WeiG-OpenWrt-AutoBuild/actions/workflows/custom-build.yml) செல்லவும். வெற்றிகரமாக முடிந்ததும் **【Artifacts】** பிரிவிலிருந்து firmware-ஐப் பதிவிறக்கவும். `CONFIG` என்பது அமைப்புகளுக்கான கோப்பு, `BUILD-LOGS` என்பது பிழை கண்டறிதல் பதிவுகள்; **இவை சாதனத்தில் எழுத வேண்டிய firmware அல்ல**. கோப்புகள் **60 நாட்கள்** இருக்கும்.

## அடிக்கடி கேட்கப்படும் கேள்விகள்

<details>
<summary>அதிகத் தொகுப்புகளால் RootFS இடம் ஏன் போதவில்லை?</summary>

தொகுப்புகளும் அவற்றின் சார்புகளும் RootFS பகுதியின் அளவை மீறலாம். சாதனம் ஆதரித்தால் **【Advanced menuconfig】** → **【Target Images】** இல் `TARGET_ROOTFS_PARTSIZE` அளவை 512 அல்லது 1024 MiB போன்ற மதிப்புக்கு மாற்றலாம். சில இயற்பியல் திசைவிகளின் flash பகுதியை மாற்ற முடியாது; அப்போது தொகுப்புகளைக் குறைக்கவும். [Issue #233](https://github.com/weigefenxiang/WeiG-OpenWrt-AutoBuild/issues/233) பார்க்கவும்.

</details>

<details>
<summary>நீண்ட உருவாக்கப் பணி ஏன் நிறுத்தப்படுகிறது?</summary>

GitHub-hosted Runner-இல் ஒரு Job பொதுவாக ஆறு மணிநேரம் வரை இயங்கும். இந்தத் திட்டத்தில் உச்சவரம்பு **350 நிமிடங்கள்**, பதிவுகளைச் சேகரிப்பதற்காக இயக்கம் **335 நிமிடங்களில்** நிறுத்தப்படும். **இது இடைநிறுத்தம் அல்ல; பின்னர் தொடர்ந்து இயக்க முடியாது**.

</details>

<details>
<summary>உருவாக்கம் தோல்வியடைந்ததற்கான காரணத்தை எப்படித் தெரிந்துகொள்வது?</summary>

**【Artifacts】** பிரிவிலிருந்து `BUILD-LOGS` பதிவிறக்கி முதலில் `00-SUMMARY.txt` படிக்கவும். RootFS அளவு, நேர வரம்பு, மூலக் குறியீடு மற்றும் சார்புகள் ஆகியவற்றின் பிழைகளை ஆராயவும். [Issue #233](https://github.com/weigefenxiang/WeiG-OpenWrt-AutoBuild/issues/233) பார்க்கவும். திருத்தியபின் **புதிய Issue** உருவாக்கவும்.

</details>

<details>
<summary>புதிய அமைப்புக்கு பழைய Run-ஐ மீண்டும் இயக்கலாமா?</summary>

முடியாது. பழைய Run முன்பு பதிவு செய்த கோரிக்கை, குறியீடு, தரவு ஆகியவற்றையே பயன்படுத்தும். புதிய கட்டமைப்பைச் சரிபார்த்து புதிய கோரிக்கை அனுப்பவும்.

</details>
