## शुरुआत: तीन चरणों में फ़र्मवेयर

**📖 [चित्रों सहित पूरी मार्गदर्शिका](https://weigshare.com/posts/WeiG-OpenWrt-AutoBuild-Guide/)**

### 1. स्रोत, उपकरण और पैकेज चुनें

[**【ऑनलाइन कॉन्फ़िगरेटर】**](https://www.weigshare.com/wrt/) खोलें और क्रम से **【Source】** → **【Branch】** → **【Target System】** → **【Subtarget】** → **【Target Profile】** चुनें। ज़रूरी पैकेज चिह्नित करें और आवश्यकता के अनुसार **【Advanced menuconfig】**, समय क्षेत्र तथा थीम बदलें। **【कॉन्फ़िगरेशन लोड करें】** से कॉन्फ़िगरेशन फ़ाइल `*.json`, `.config` या `config.buildinfo` आयात कर सकते हैं। आगे बढ़ने से पहले स्रोत, उपकरण और प्लगइन जाँचें।

### 2. GitHub पर क्लाउड बिल्ड अनुरोध भेजें

पहले [**【GitHub में साइन इन करें】**](https://github.com/login), फिर [**【कॉन्फ़िगरेटर】**](https://www.weigshare.com/wrt/) पर लौटकर **【क्लाउड बिल्ड शुरू करें】** → **【कॉन्फ़िगरेशन डाउनलोड करें और GitHub खोलें】** दबाएँ। ब्राउज़र `*.json` फ़ाइल डाउनलोड कर GitHub Issue फ़ॉर्म खोलेगा। कंप्यूटर पर अभी डाउनलोड की गई JSON फ़ाइल बिल्ड अनुरोध वाले खाने में खींचकर अपलोड करें, फिर **【Submit new issue】** पर क्लिक करें। बॉट जवाब में बिल्ड का लिंक देगा।

<details>
<summary><strong>महत्त्वपूर्ण सुझाव (विस्तार करें)</strong></summary>

> पृष्ठ के नीचे दाएँ फ़्लोटिंग टूलबार में **【जाँच】** दबाकर सेटिंग और संगतता की सलाह पहले देख सकते हैं। **【कॉन्फ़िगरेशन डाउनलोड करें और GitHub खोलें】** दबाने पर पूर्व-जाँच अपने-आप भी चलती है।
>
> समस्या मिलने पर सुझाया सुधार लागू करें या **【जैसा है रखें और ज़बरदस्ती आगे बढ़ें】** चुनें। इससे मूल स्रोत की खराबी ठीक नहीं होती और बिल्ड असफल हो सकता है।
>
> पहले से भरी जानकारी बचाने के लिए कॉन्फ़िगरेटर द्वारा खोले गए GitHub Issue फ़ॉर्म का ही उपयोग करें।
>
> केवल JSON डाउनलोड करने से **बिल्ड शुरू नहीं होता**; Issue भेजना ज़रूरी है।
>
> सार्वजनिक Issues, अनुरोध या लॉग में असली पासवर्ड, टोकन और गोपनीय जानकारी न डालें।

</details>

### 3. फ़र्मवेयर डाउनलोड करें

Issue का लिंक खोलें या [**【Actions → Firmware Download】**](https://github.com/weigefenxiang/WeiG-OpenWrt-AutoBuild/actions/workflows/custom-build.yml) पर जाएँ। सफल होने पर **【Artifacts】** से फ़र्मवेयर डाउनलोड करें। `CONFIG` में सेटिंग और `BUILD-LOGS` में जाँच लॉग होते हैं; **ये उपकरण में फ़्लैश करने वाले फ़र्मवेयर नहीं हैं**। फ़ाइलें **60 दिन** उपलब्ध रहती हैं।

## अक्सर पूछे जाने वाले प्रश्न

<details>
<summary>बहुत पैकेज चुनने पर RootFS की जगह क्यों कम पड़ती है?</summary>

पैकेज और उनकी निर्भरताएँ RootFS पार्टिशन से बड़े हो सकते हैं। उपकरण अनुमति दे तो **【Advanced menuconfig】** → **【Target Images】** में `TARGET_ROOTFS_PARTSIZE` को, उदाहरण के लिए, 512 या 1024 MiB करें। कुछ भौतिक राउटर का फ़्लैश विभाजन निश्चित होता है; उनमें पैकेज घटाएँ। उदाहरण: [Issue #233](https://github.com/weigefenxiang/WeiG-OpenWrt-AutoBuild/issues/233)।

</details>

<details>
<summary>लंबी बिल्ड समय सीमा पर क्यों रुकती है?</summary>

GitHub-hosted Runner के एक Job की सामान्य सीमा छह घंटे है। यह परियोजना **350 मिनट** और निष्पादन की सीमा **335 मिनट** रखती है ताकि लॉग जमा हो सकें। बिल्ड **पूरी तरह रुकती है, बाद में जारी करने के लिए विराम नहीं लेती**।

</details>

<details>
<summary>असफल बिल्ड की वजह कैसे पता करें?</summary>

**【Artifacts】** से `BUILD-LOGS` डाउनलोड करें और पहले `00-SUMMARY.txt` पढ़ें। RootFS, समय सीमा, स्रोत कोड और निर्भरता संबंधी त्रुटियाँ देखें। [Issue #233](https://github.com/weigefenxiang/WeiG-OpenWrt-AutoBuild/issues/233) भी देखें। सुधार के बाद **नया Issue** बनाएँ।

</details>

<details>
<summary>क्या नए बदलाव के लिए पुराना Run दोबारा चला सकते हैं?</summary>

नहीं। पुराना Run उसी पुराने अनुरोध, कोड और डेटा को उपयोग करता है। नया कॉन्फ़िगरेशन जाँचकर नया अनुरोध भेजें।

</details>
