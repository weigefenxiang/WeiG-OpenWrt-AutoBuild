## 시작하기: 세 단계로 펌웨어 만들기

**📖 [이미지와 함께 보는 전체 사용법](https://weigshare.com/posts/WeiG-OpenWrt-AutoBuild-Guide/)**

### 1. 소스, 장치, 패키지 선택

[**【온라인 설정 페이지】**](https://www.weigshare.com/wrt/)에서 **【Source】** → **【Branch】** → **【Target System】** → **【Subtarget】** → **【Target Profile】** 순서로 선택합니다. **【② 플러그인 선택】**에서 기능을 고르고 필요하면 **【Advanced menuconfig】**, 시간대, 테마 등을 조정하세요.

기존 설정은 **【설정 불러오기】**에서 설정 파일 `*.json`, `.config`, `config.buildinfo`를 가져올 수 있습니다. 소스와 장치, 선택한 패키지를 확인한 뒤 진행하세요.

### 2. GitHub 클라우드 빌드 요청

먼저 [**【GitHub에 로그인】**](https://github.com/login)한 뒤 [**【설정 페이지】**](https://www.weigshare.com/wrt/)로 돌아가 **【클라우드 빌드 요청】** → **【설정 다운로드 후 GitHub 열기】**를 누릅니다. `*.json` 설정 파일이 다운로드되고 GitHub Issue 페이지가 열립니다. PC에서는 받은 JSON을 입력란에 끌어다 놓은 다음 **【Submit new issue】**를 누릅니다.

Issue를 제출하면 봇이 해당 빌드 실행 링크를 댓글로 알려줍니다.

<details>
<summary><strong>주의사항 (눌러서 펼치기)</strong></summary>

> **안내:** 오른쪽 아래 플로팅 도구 모음의 **【점검】** 버튼으로 설정 오류와 호환성 권장 사항을 미리 확인할 수 있습니다. **【설정 다운로드 후 GitHub 열기】**에서도 검사가 자동으로 실행됩니다.
>
> 문제가 발견되면 권장 수정 사항을 적용하거나 **【유지하고 강제 진행】**을 선택할 수 있습니다. 강제 진행은 상위 소스의 오류를 해결하지 않으며 컴파일 실패 가능성이 남습니다.
>
> 미리 채워진 요청 정보가 사라지지 않도록 설정 페이지에서 자동으로 연 GitHub Issue 양식을 이용하세요.
>
> JSON만 내려받고 Issue를 제출하지 않으면 **빌드가 시작되지 않습니다**.
>
> 공개 Issue, 빌드 요청, 로그에 실제 비밀번호나 토큰 같은 민감한 정보를 게시하지 마세요.

</details>

### 3. 펌웨어 받기

Issue에 남은 링크 또는 [**【Actions → Firmware Download】**](https://github.com/weigefenxiang/WeiG-OpenWrt-AutoBuild/actions/workflows/custom-build.yml)에서 실행 내역을 확인합니다. 성공하면 페이지 아래의 **【Artifacts】**에서 펌웨어를 받으세요. `CONFIG`는 설정 파일, `BUILD-LOGS`는 진단 로그이므로 **펌웨어처럼 플래싱하면 안 됩니다**. 파일은 **60일간** 보관됩니다.

## 자주 묻는 질문

<details>
<summary>패키지를 많이 선택하면 RootFS 용량이 부족한 이유는 무엇인가요?</summary>

패키지와 그에 필요한 의존 패키지가 RootFS 파티션 크기를 초과할 수 있습니다. 장치가 지원한다면 **【Advanced menuconfig】** → **【Target Images】**에서 `TARGET_ROOTFS_PARTSIZE`를 찾아 필요에 따라 512 또는 1024 MiB 등으로 조정하세요. 실제 하드웨어 라우터는 플래시 용량과 파티션 구조 때문에 변경할 수 없는 경우가 있으므로 그때는 패키지를 줄여야 합니다. 사례: [Issue #233](https://github.com/weigefenxiang/WeiG-OpenWrt-AutoBuild/issues/233).

</details>

<details>
<summary>빌드가 오래 걸리면 왜 중단되나요?</summary>

GitHub 호스팅 Runner의 작업은 일반적으로 최대 6시간입니다. 이 프로젝트는 Job 한도를 **350분**, 실행 마감 시간을 **335분**으로 설정해 로그 수집 시간을 남겨 둡니다. 제한에 도달하면 **일시 정지가 아닌 종료**이므로 나중에 이어서 실행할 수 없습니다. Node.js나 Rust 의존성은 빌드 시간을 늘릴 수 있습니다.

</details>

<details>
<summary>실패한 빌드는 어떻게 진단하나요?</summary>

해당 Run의 **【Artifacts】**에서 `BUILD-LOGS`를 내려받고 `00-SUMMARY.txt`부터 확인하세요. RootFS 용량, 시간 제한, 상위 소스 또는 의존성 오류를 구분해야 합니다. [Issue #233](https://github.com/weigefenxiang/WeiG-OpenWrt-AutoBuild/issues/233)을 참고하고 설정을 고쳤다면 **새 Issue**를 제출하세요.

</details>

<details>
<summary>설정을 바꾼 뒤 이전 Run을 다시 실행해도 되나요?</summary>

아니요. 이전 Run은 당시 고정된 요청, 코드, 데이터를 그대로 사용합니다. 현재 사이트에서 설정을 다시 불러와 검사하고 새 요청 및 Issue를 만드세요.

</details>

## 개발 및 배포

사이트로 펌웨어를 빌드하는 데는 저장소 복제나 Node.js 설치가 필요하지 않습니다. 개발 관련 내용은 [개발자 안내서(영어)](../docs/DEVELOPER.md) 및 [아키텍처 문서(영어)](ARCHITECTURE/ARCHITECTURE.md)를 참고하세요.

## Menuconfig Catalog

[Menuconfig Catalog](https://github.com/weigefenxiang/WeiG-OpenWrt-Menuconfig-Catalog)는 소스 브랜치, 장치 Profile, 패키지, Kconfig 의존성과 호환성 정보를 수집하고 공개합니다. 웹과 클라우드 빌드가 같은 데이터를 사용하므로 AutoBuild에 별도의 장치·패키지 데이터베이스를 만들지 않습니다.
